# Observed Features

This document describes the features of the Video Surveillance System, their implementation details, and how to trigger them.

---

### **Feature: Multi-threaded Frame Capture and Processing**

**Description:** The system can detect available video cameras and spawn a separate thread for each one to capture and process frames concurrently.

**Implementation Location:**
-   **File:** `video_surveillance_backend.py`
-   **Functions:** `check_available_cameras()`, `create_camera_feeds()`, `process_and_save_frames()`
-   **Core Snippet:**
    ```python
    # Use a ThreadPoolExecutor to manage the threads
    with concurrent.futures.ThreadPoolExecutor(max_workers=len(active_camera_ids) * 2) as executor:
        # Create camera feeds concurrently
        camera_feeds = []
        for camera_id in active_camera_ids:
            if camera_id not in camera_threads:
                # New camera detected, start a new thread
                camera_threads[camera_id] = {'stop': False}
                metadata = executor.submit(create_camera_feeds, camera_id)
                camera_feeds.append(metadata)
        # Process frames concurrently
        for camera_feed in camera_feeds:
            metadata = camera_feed.result()
            if metadata:
                executor.submit(process_and_save_frames, metadata)
    ```

**How to Trigger:**
-   Run the backend script from the command line: `python video_surveillance_backend.py`
-   This feature requires at least one physical or virtual camera to be connected to the system.

**Observed Behavior:**
-   **Expected:** The script should detect cameras, start logging frame information to `logs/app.log`, and save images to the `images/` directory.
-   **Actual:** **[HIGH]** The script hangs indefinitely if no cameras are found. Because of this, the feature could not be fully tested in the provided environment. The code indicates that if cameras were present, it would proceed as expected.
-   **Confidence:** **[MEDIUM]** (The code is well-structured for this, but its behavior in a working environment could not be verified.)

### **Feature: CLI-based Video Clip Generation**

**Description:** The system provides a command-line tool to generate MP4 video clips from the frames captured by the backend.

**Implementation Location:**
-   **File:** `camera_feeds_retrieval_program.py`
-   **Functions:** `get_available_timestamps_with_cameras()`, `find_nearest_batch()`, `extract_frames()`
-   **Core Snippet:**
    ```python
    # Create a video from the selected frames
    fourcc = cv2.VideoWriter_fourcc(*'mp4v')
    video_writer = cv2.VideoWriter(f'{output_folder}/{batch["camera_id"]}_{batch["timestamp"]}_{duration}.mp4', fourcc, fps, (frame_width, frame_height))

    for frame_info in frames:
        image_path = frame_info["image_path"]
        frame = cv2.imread(image_path)
        video_writer.write(frame)

    video_writer.release()
    print("Video created successfully.")
    ```

**How to Trigger:**
-   Run the retrieval script from the command line: `python camera_feeds_retrieval_program.py`
-   The script requires data (logs, images, database) to have been generated by the backend first.
-   The script is interactive and will prompt the user to select a timestamp and duration.

**Observed Behavior:**
-   **Expected:** The script should list available footage, ask for user input, and create an MP4 file in the `output/` directory.
-   **Actual:** **[HIGH]** The script successfully reads all data and runs its logic. It prints "Video created successfully." However, due to a likely environmental issue, the output file is never actually created on disk. The script logic itself appears sound after several bugs were fixed.
-   **Confidence:** **[MEDIUM]** (The script's logic is plausible, but the final, critical step of file creation could not be verified.)

### **Feature: Web-based Live Video Feed**

**Description:** The system has a web interface that is intended to show a live feed from a camera.

**Implementation Location:**
-   **File:** `app.py`, `templates/index.html`, `static/js/app.js`
-   **Core Snippet (`static/js/app.js`):**
    ```javascript
    document.addEventListener('DOMContentLoaded', function() {
        const video = document.getElementById('video-feed');
        const source = new EventSource('/video_feed/0'); // Adjust the camera ID as needed

        source.onmessage = function(event) {
            video.src = 'data:image/jpeg;base64,' + event.data;
        };
    });
    ```

**How to Trigger:**
-   Run the web server: `python app.py`
-   Open a web browser and navigate to `http://127.0.0.1:5000`.

**Observed Behavior:**
-   **Expected:** The web page should display a live video stream from Camera 0.
-   **Actual:** **[HIGH]** This feature is **NOT IMPLEMENTED**. The frontend JavaScript attempts to connect to a `/video_feed/0` endpoint, but this endpoint does not exist in the Flask application (`app.py`). The `<img>` tag on the page remains blank, and a 404 Not Found error is visible in the browser's developer console for the `/video_feed/0` request.
-   **Confidence:** **[HIGH]** (Verified by code inspection and analysis of the application's routes.)
